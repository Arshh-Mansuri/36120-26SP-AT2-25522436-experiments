## Prediction targets

| Target | Type | Horizon | Definition |
|---|---|---|---|
| Climate Comfort Index (CCI) | Regression (0–100) | Next 3 days (t+1, t+2, t+3) | Weighted temperature, humidity, wind, cloud and rain comfort scores |
| Weather Hazard Category (WHC) | Multiclass classification | Exactly t+7 | Weather Hazard Index binned into Low / Moderate / High / Extreme Risk |

Only data before **2026-01-01** is used. Data from 2026 onwards is treated as production data.

## Setup

Requirements: [uv](https://docs.astral.sh/uv/) and Python 3.12 (uv installs it automatically).

```bash
# 1. Install dependencies (includes the custom package shiftguard from TestPyPI)
make requirements            # or: uv sync

# 2. Download Open-Meteo data (1980-2025, ~5 minutes) and build the processed dataset
make data                    # or: uv run python -m weather_experiments.dataset

# 3. Run the tests
make test                    # or: uv run pytest tests

# 4. Open the notebooks
uv run jupyter lab
```

The dataset step writes:

- `data/raw/hourly_by_year/` – one parquet file per year, cached so reruns are incremental
- `data/raw/sydney_hourly_1980_2025.parquet` – all hourly observations
- `data/processed/sydney_daily.parquet` – daily observations, same-day `cci`/`whi`/`whc` and the
  prediction targets `target_cci_t1..t3` and `target_whc_t7`

## Custom package

Reusable logic lives in the custom package **`shiftguard`** from AT1
([repo](https://github.com/Arshh-Mansuri/36120-26SP-group6-25522436-package),
[TestPyPI](https://test.pypi.org/project/shiftguard/)). Version 0.2.0 extends it with
`shiftguard.weather`: Open-Meteo retrieval, daily aggregation, target formulas, leakage-safe feature
engineering, chronological splits, baselines and metrics. The API repository uses the same package.
The original AT1 drift tools (`adversarial_auc`, `drift_report`, `TemporalGapSplit`) are used to
measure distribution shift between the training period and recent years.

```bash
pip install -i https://test.pypi.org/simple/ --extra-index-url https://pypi.org/simple shiftguard
```

## Notebooks

| Notebook | Contents |
|---|---|
| `notebooks/comfort_climate/36120-26SP-AT2-25522436-comfort_climate-experiment-1.ipynb` | CCI regression experiment |
| `notebooks/weather_hazard/36120-26SP-AT2-25522436-weather_hazard-experiment-1.ipynb` | WHC classification experiment |

Hyperparameters are tuned with Optuna on three expanding-window folds (scored on 2014–16, 2017–19 and
2020–22). The notebooks read the saved results from `reports/*_tuning*.{csv,json}`. To reproduce them
(takes about 1–2 hours per target):

```bash
N_JOBS=4 OMP_NUM_THREADS=4 uv run python -m weather_experiments.modeling.tune --trials 12 --target both
```

## Results (test period 2023–2025, never used for model selection)

| Target | Final model | Test result | Best baseline |
|---|---|---|---|
| CCI t+1 / t+2 / t+3 | Mean of tuned XGBoost + LightGBM (89 features) | MAE 5.93 / 6.98 / 7.29 | 7.47 / 7.53 / 7.53 |
| WHC t+7 | Tuned XGBoost, class weights `balanced ** 0.72` (161 features) | Macro-F1 0.277 | 0.256 (monthly climatology) |

The WHC model beats the baselines, but it did not identify any of the 45 High/Extreme test days.
Details and discussion are in the notebooks and the final report.

## Project organisation

```
├── Makefile               <- `make requirements`, `make data`, `make test`, `make lint`
├── pyproject.toml         <- Dependencies and tool configuration
├── data/                  <- Generated by `make data` (not committed)
├── models/
│   ├── comfort_climate/   <- Final CCI model artefacts + metadata.json
│   └── weather_hazard/    <- Final WHC model artefacts + metadata.json
├── notebooks/
│   ├── comfort_climate/   <- CCI experiment notebooks
│   └── weather_hazard/    <- WHC experiment notebooks
├── reports/               <- Experiment reports
│   └── figures/           <- Figures used in the final report
├── tests/                 <- Data sanity tests
└── weather_experiments/   <- Project source code
    ├── config.py          <- Paths, location, date boundaries, split dates
    ├── dataset.py         <- Open-Meteo download and processed dataset build
    ├── features.py        <- Model table (shiftguard features + targets), feature groups
    └── modeling/
        ├── compare.py     <- Baseline / algorithm / feature-set comparison
        ├── tune.py        <- Optuna tuning (time-series folds)
        └── predict.py     <- Offline inference with the saved artefacts for a given date
```

Final models are trained and saved in section K of each notebook (refitted on all labelled data up to
2025). Check them offline with `uv run python -m weather_experiments.modeling.predict 2025-06-01`.
